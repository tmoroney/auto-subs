## 2026-12-10 - ExtendScript Code Injection Prevention in evalFile Bridge
**Vulnerability:** In `Adobe-Extension/src/js/lib/utils/bolt.ts`, `evalFile` dynamically constructed an ExtendScript evaluation script via string concatenation: `"typeof $ !== 'undefined' ? $.evalFile(\"" + file + "\") : fl.runScript(FLfile.platformPathToURI(\"" + file + "\"));"`. If `file` contained double quotes, backslashes, newlines, or ExtendScript code fragments (e.g. `"); app.quit(); //`), it allowed escaping string literal boundaries and executing arbitrary ExtendScript commands in the host Adobe application with project/OS filesystem privileges.
**Learning:** String interpolation into script contexts (`evalScript`, `evalES`, `$.evalFile`) in CEP panels must never concatenate raw string variables. Even file paths can contain quotes or malicious injection payloads if originated from untrusted input or path construction.
**Prevention:** Always serialize parameters into ExtendScript code strings using `JSON.stringify` (or parameterized invocation via `evalTS`), properly escaping quotes, backslashes, control characters, and line breaks before evaluation.

## 2026-12-03 - Path Traversal Prevention in Adobe CEP Audio Export Bridge
**Vulnerability:** In `Adobe-Extension/src/js/main/useWebSocket.ts`, incoming `request_audio_export` WebSocket messages received `exportFolder` and optional `presetPath` arguments with only primitive string type checks. These paths were passed directly into ExtendScript `exportSequenceAudio`, which in After Effects created directories via `new Folder(outputFolder).create()` and in Premiere Pro exported media to `outputFolder + filename` using `externalPresetPath` via `new File(externalPresetPath)`. Malicious payloads with directory traversal (`..`), null bytes, or non-.epr extensions could create arbitrary directories, write rendered audio files to sensitive filesystem locations, or reference unauthorized files.
**Learning:** File and directory paths received over local IPC or WebSocket bridges to host creative applications must be rigorously validated for traversal sequences, length constraints, control characters, and expected extensions before being forwarded to host scripting environments (ExtendScript) which operate with full filesystem privileges.
**Prevention:** Validate export folder paths with `isValidExportFolderPath` (forbidding `..`, null bytes, control characters) and optional export preset paths with `isValidPresetFilePath` (enforcing `.epr` extension, forbidding `..` and control characters).

## 2026-11-26 - Path Traversal Prevention in Adobe CEP SRT Import Bridge
**Vulnerability:** In `Adobe-Extension/src/js/main/useWebSocket.ts`, incoming `request_import_srt` WebSocket messages accepted arbitrary `filePath` strings without validation, passing them directly to ExtendScript `importSRTFile` (`app.project.importFiles` in Premiere or `new File(filePath).read()` in After Effects). Malicious or malformed inputs containing directory traversal (`..`), null bytes, or non-SRT extensions could target arbitrary filesystem locations.
**Learning:** WebSocket handlers accepting filesystem paths from local bridge protocols must enforce path traversal checks and strict file extension constraints before invoking host-level scripting or application file import APIs.
**Prevention:** Validate incoming file paths with `isValidSrtFilePath`, verifying string bounds, forbidding path traversal (`..`), rejecting control characters/null bytes, and strictly requiring the `.srt` extension.

## 2026-11-19 - Safe External URL Validation in Adobe CEP Extension
**Vulnerability:** In `Adobe-Extension/src/js/lib/utils/bolt.ts`, `openLinkInBrowser` invoked `csi.openURLInDefaultBrowser` (or `location.href`) with arbitrary user or bridge-supplied URL strings without protocol validation, allowing potential execution of dangerous schemes (`javascript:`, `file:`, `data:`, `shell:`).
**Learning:** Browser/OS-level opener bridges in Adobe CEP extensions can execute arbitrary URI schemes unless strictly validated on the client side, bypassing expected web browsing boundaries.
**Prevention:** Strictly validate that external navigation targets use safe web schemes (`http:` or `https:`) before passing them to `csi.openURLInDefaultBrowser` or assigning `location.href`.

## 2026-11-12 - Prototype Pollution and Input Sanitization in Preset Import
**Vulnerability:** In `AutoSubs-App/src/contexts/PresetsContext.tsx`, `parseImportedPreset` accepted user-supplied JSON from clipboard paste or file imports without bounds on string lengths, without stripping dangerous control characters, and without guarding nested `macroSettings` objects against prototype pollution keys (`__proto__`, `constructor`, `prototype`).
**Learning:** External configuration objects loaded into persistent application stores and passed down to component trees or native scripting bridges can pollute JavaScript prototypes or degrade application performance if not validated for key safety and input length boundaries.
**Prevention:** Sanitize object keys recursively to reject prototype-polluting keys (`__proto__`, `constructor`, `prototype`), enforce strict character length and control character constraints on human-readable metadata, and validate numeric version fields before persisting.

## 2026-11-05 - Path Traversal Prevention in Caption Preset Previews
**Vulnerability:** Preset IDs and preview filenames in `AutoSubs-App/src/lib/caption-previews.ts` were joined directly into filesystem paths without validation, allowing path traversal (`../`) to access, delete, or overwrite arbitrary files outside the `caption-previews` folder.
**Learning:** Functions that manage user-contributed or imported assets (such as preset previews) must strictly validate IDs and filenames using whitelist validation (alphanumeric/hyphens/underscores and `.png` extension) before passing them to Tauri filesystem and asset protocol APIs.
**Prevention:** Always validate asset IDs and filenames with dedicated sanitizers/validators before joining them with application storage directories, rejecting directory traversal characters, null bytes, and non-whitelisted extensions.

## 2026-10-30 - Safe External URL Navigation and Opener Capability Enforcement
**Vulnerability:** External URLs rendered from remote GitHub release notes in Markdown and promotional CTA cards invoked `@tauri-apps/plugin-shell`'s unconstrained `open` method without protocol validation. This permitted arbitrary URI scheme execution (such as `file://`, `javascript:`, or malicious protocol handlers) and bypassed Tauri v2's capability configuration for `@tauri-apps/plugin-opener`.
**Learning:** In Tauri v2 applications, `@tauri-apps/plugin-shell:open` executes whatever URI or binary target is passed if permitted, while `@tauri-apps/plugin-opener:open_url` enforces permission scopes configured under `capabilities/default.json` (`opener:allow-open-url`).
**Prevention:** Always use `@tauri-apps/plugin-opener` (`openUrl`), validate that external navigation targets strictly use safe web schemes (`https://` or `http://`), and whitelist allowed external domains in Tauri capabilities.
